## 2. Mandatory principles (his words, keep them)

1. **Read-only by default.** The app sends nothing until the user turns on **LIVE** (live control).
   When connected and not live, any hand change shows a toast "קריאה בלבד…" and is reverted.
2. **Nothing changes on the mixer without a manual action.**
   > "חשוב לשים לב בכל דבר ובמיוחד בFX שזה לא משנה את מה שקיים כבר במיקסר בלי שמגדירים ידנית.
   > לדוגמה קרה לנו בעבר שהפעלת אוסילטור גרמה לו לצאת מערוץ שלא הוגדר ידנית. אני רוצה גם
   > שבאפקטים, שהקריאה מהמיקסר את המצב הקיים תהיה נכונה, והחלפה תתבצע בפעולה שאני עושה ולא
   > אוטומטית לפי איך ששיחקתי במצב דמו."
   - Demo play never reaches the desk. Default values are display-only.
   - Opening a screen is not an edit. Reading a value back is not an edit.
3. **Never "correct" the desk.** If the app shows a value differently from the desk (unknown enum,
   rounding, lossy mapping), it must not write it back. See the send guard (section 5).
4. **Reading the desk correctly comes first** (names, colours, icons, FX state, cuts, types).
5. Demo mode when not connected; it must look alive (meters, RTA) but is fully separate.

## 4. Lessons from the bugs (do not repeat)

1. **Infinite read→write loop** (Triple DEQ): reading values changed state → treated as an edit →
   pushed → re-read… froze the whole app ("doesn't see the mixer, channels wrong"). Fix: remember
   what was read (`fdeqRead`) and never push a state that came from the desk.
2. **One bad screen killed the app.** Render is wrapped (`render()` → `renderApp()` in try/catch): on
   error log it, go back to the mixer screen with a toast, keep the link alive. Keep this.
3. **Names / colours / icons**: WING strips can show their **input's** name/colour/icon (CUST LINK).
   Read the *shown* values (`$name`, `$col`, `$icon`), write to the input when linked. An empty name
   answer must never wipe a real name (`nameIn`). Demo names/colours are cleared on connect.
   The icon numbering (desk vs our 125-icon table) is still **unresolved** – plan first, ask him.
4. **Lossy mapping wrote back to the desk**: bus L/H band types (CUT, BW/BS/LR 6..48) were mapped to
   "bell" and written back on the next tap → his low/high cuts were erased live. Fix: support all
   types; **and** the general send guard (section 5).
5. **Two sources for one value** (native vs OSC) made colours flicker. Pick one source per value.
6. Render loops / heavy per-frame work kill the link; keep thumbnails cached, avoid work in ticks.

## 5. The send guard (core safety – port it)

`syncCheck()` runs on every update and every 250 ms:
- While idle (>1.5 s since the last pointer/key/input event, captured on `document`), it stores the
  derived "what the app would write" for every strip as the **base**. Nothing is sent.
- During an action it sends only keys where the app value differs from the desk **and** from the base
  (= the user changed it). A strip seen for the first time just gets a base.
- So a value the app merely shows differently is never written. Sent keys are dropped from the base.
